## VM infrastructure and images

- `/dev/kvm` exists; libvirt and virt-install are available.
- `virsh --readonly --connect qemu:///system list --all` returned no VMs.
  This covers system libvirt, not every possible user session/hypervisor.
- The system libvirt `default` network is active, persistent, and autostarted.
  Its XML specifies NAT on `virbr0`, gateway `192.168.122.1/24`, and DHCP range
  `192.168.122.2` through `192.168.122.254`. Guest reachability was not tested;
  do not assume a NAT guest is directly reachable from the Mac or an AAP EE.
- Pools `default`, `iso`, and `vms` are active and autostarted. Pool XML confirms
  `vms` at `/home/diem/vms` and `iso` at `/home/diem/iso`.
  The `vms` directory currently has a `user_home_t` SELinux label; verify guest
  disk access and appropriate labels when provisioning rather than disabling
  SELinux. The `default` pool path was not rechecked on September 16.
- `/home/diem/rhel-10.2-x86_64-kvm.qcow2` exists (about 1.1 GiB on disk).
- `/home/diem/rhel-9.8-x86_64-kvm.qcow2` exists (about 1.3 GiB on disk).

These QCOW2 files are VM disk images, not Podman images or provisioned guests.
Preserve source images when creating guest disks. The earlier development-VM
attempt prepared temporary cloud-init data but did not create a VM. Do not
resume it or reuse its proposed resource allocation as an approved plan.
